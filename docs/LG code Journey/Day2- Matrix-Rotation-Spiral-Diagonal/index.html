Day2 - Matrix_Rotation & Spiral & Diagonal

Date: 13/04/2026 Topic: Matrix: Rotation, Spiral, Diagonal Total Problems Solved: 4

I. THEORY​

🔄 MATRIX ROTATION 90°​

1. Definition​

Transform a matrix so that its elements are rotated 90° (typically clockwise).

2. Core Idea​

Transpose + Reverse

  • Swap rows ↔ columns (transpose)
  • Reverse each row

3. When to Use​

Indicators:

  • "Rotate matrix", "Rotate image"
  • Rotate 90°, 180°

Related Patterns:

  • Element position transformation
  • No extra array needed (in-place)

4. Complexity​

TypeComplexity
TimeO(n²)
SpaceO(1)

5. Common Pitfalls​

  • Forgetting to reverse after transpose
  • Wrong direction (clockwise vs counter-clockwise)
  • Incorrect swap (overwriting data)

🌀 SPIRAL TRAVERSAL​

1. Definition​

Traverse a matrix in a spiral pattern from the outside in.

2. Core Idea​

Use 4 boundaries: top, bottom, left, right and gradually shrink the range.

3. When to Use​

Indicators:

  • "Spiral matrix"
  • "Print in spiral order"

Related Patterns:

  • Layer-by-layer traversal
  • Shrink boundaries after each loop

4. Complexity​

TypeComplexity
TimeO(n × m)
SpaceO(1)

5. Common Pitfalls​

  • Forgetting to check top <= bottom, left <= right
  • Visiting duplicate elements
  • Wrong direction order (→ ↓ ← ↑)

↗️ DIAGONAL TRAVERSAL​

1. Definition​

Group or traverse elements that lie on the same diagonal.

2. Core Idea​

Two critical formulas:

  • i + j = const → anti-diagonal
  • i - j = const → main diagonal

3. When to Use​

Indicators:

  • "Diagonal traversal"
  • "Group by diagonal"

Related Patterns:

  • HashMap / Dictionary by key
  • Group-based traversal

4. Complexity​

TypeComplexity
TimeO(n × m)
SpaceO(n × m)

5. Common Pitfalls​

  • Confusing i+j and i-j
  • Not handling order (reverse when zigzag is needed)
  • Negative keys (with i-j)

II. PROBLEMS​

Problem 1: Rotate Image — LeetCode​

1. Problem Summary​

  • Given an n x n square matrix
  • Requirement: rotate 90° clockwise
  • Important: must be done in-place — no new matrix allowed

2. Approach​

Why this solution:

  • Creating a new matrix → easy but violates in-place requirement
  • Optimal approach: Transpose + Reverse

Patterns applied:

  • Array + Matrix transformation
  • In-place manipulation
  • Symmetry (reflection over main diagonal)

Theory connection:

  • Matrix rotation = geometric transformation
  • Mapping formula: (i, j) → (j, n - i - 1)
  • Implemented via: Transpose (axis swap) → Reverse (horizontal flip)

3. Solution Idea​

Step 1: Transpose

matrix[i][j] ↔ matrix[j][i]   →   rows become columns

Step 2: Reverse each row

Flip horizontally to complete the 90° rotation

Thought flow:

Original Matrix
      ↓
  Transpose
      ↓
 Reverse Row
      ↓
Rotated Matrix (90° CW)

💡 Key Insight: Rotate 90° = (reflect over main diagonal) + (horizontal flip)

4. Code​

class Solution:
    def rotate(self, matrix):
        n = len(matrix)

        # Step 1: Transpose
        for i in range(n):
            for j in range(i, n):
                matrix[i][j], matrix[j][i] = matrix[j][i], matrix[i][j]

        # Step 2: Reverse each row
        for row in matrix:
            row.reverse()

5. Complexity​

TypeComplexity
TimeO(n²)
SpaceO(1)

5. Key Learnings​

Insight:

Many "rotate / transform matrix" problems are just combinations of simple transformations.

Pattern reuse: Transpose + Reverse is used in:

  • Rotate matrix
  • Image processing
  • Some simulation problems

Watch out for:

  • Using auxiliary matrix → fails in-place requirement
  • Confusing column reverse vs row reverse
  • Incorrect swap causing data loss

Problem 2: Spiral Matrix — LeetCode​

1. Problem Summary​

  • Given an m x n matrix
  • Requirement: return all elements in spiral order (→ ↓ ← ↑ repeated)

Example:

[[1,2,3],[4,5,6],[7,8,9]] → [1,2,3,6,9,8,7,4,5]

2. Approach​

Why this solution:

  • Option 1: Visited matrix → easy to understand but wastes space
  • Option 2: 4-boundary approach → more optimal (preferred in interviews)
  • Choice: 4 boundaries (top, bottom, left, right)

Patterns applied:

  • Matrix traversal
  • Simulation (simulating movement)
  • Layer-by-layer traversal

Theory connection:

  • Spiral = progressively shrinking rectangle
  • Each loop: → (top) → ↓ (right) → ← (bottom) → ↑ (left)
  • After each loop: top++, right--, bottom--, left++

3. Solution Idea​

Initialize 4 variables:

top = 0,  bottom = m - 1
left = 0, right = n - 1

Process:

  1. Traverse top row: left → right, then top++
  2. Traverse right column: top → bottom, then right--
  3. Traverse bottom row (if any): right → left, then bottom--
  4. Traverse left column (if any): bottom → top, then left++

Repeat until all elements are collected.

4. Code​

class Solution:
    def spiralOrder(self, matrix):
        res = []

        top, bottom = 0, len(matrix) - 1
        left, right = 0, len(matrix[0]) - 1

        while top <= bottom and left <= right:
            # 1. left → right
            for i in range(left, right + 1):
                res.append(matrix[top][i])
            top += 1

            # 2. top → bottom
            for i in range(top, bottom + 1):
                res.append(matrix[i][right])
            right -= 1

            # 3. right → left
            if top <= bottom:
                for i in range(right, left - 1, -1):
                    res.append(matrix[bottom][i])
                bottom -= 1

            # 4. bottom → top
            if left <= right:
                for i in range(bottom, top - 1, -1):
                    res.append(matrix[i][left])
                left += 1

        return res

5. Complexity​

TypeComplexity
TimeO(m × n)
SpaceO(1)

6. Key Learnings​

Insight:

This is a textbook boundary control problem. The challenge isn't the idea — it's writing bug-free code.

Pattern reuse:

  • Spiral Matrix II (generate matrix)
  • Boundary traversal
  • Grid simulation

Watch out for:

  • Missing conditions: if top <= bottom, if left <= right
  • Visiting duplicate elements
  • Wrong direction order
  • Index misalignment when updating boundaries

Problem 3: Matrix Multiplication — Programmers​

1. Problem Summary​

  • Given 2 matrices: arr1 of size n × m and arr2 of size m × k
  • Requirement: return the product of the two matrices
  • Condition: number of columns of matrix 1 = number of rows of matrix 2

2. Approach​

Why this solution:

  • Basic DSA + math problem — no tricks needed
  • Use the direct definition of matrix multiplication
  • Standard approach: Triple nested loop

Patterns applied:

  • Matrix traversal
  • Simulation
  • Nested loop (3 layers)

Theory connection:

  • Formula: C[i][j] = Σ (A[i][k] * B[k][j])
  • Each element = dot product between row i of A and column j of B

3. Solution Idea​

For each element result[i][j]:

for i (row A):
    for j (col B):
        for k (shared dimension):
            result[i][j] += A[i][k] * B[k][j]

💡 Key Insight: "Row of A × Column of B"

4. Code​

def solution(arr1, arr2):
    n = len(arr1)
    m = len(arr1[0])
    k = len(arr2[0])

    # create result matrix
    result = [[0] * k for _ in range(n)]

    for i in range(n):
        for j in range(k):
            for t in range(m):
                result[i][j] += arr1[i][t] * arr2[t][j]

    return result

5. Complexity​

TypeComplexity
TimeO(n × m × k)
SpaceO(n × k)

5. Key Learnings​

Insight:

Matrix multiplication = 3 loops + dot product

Pattern reuse:

  • Image processing
  • Graph adjacency matrix
  • DP on matrices
  • Linear algebra problems

Watch out for:

  • Index confusion: arr1[i][k] * arr2[k][j] ✅ vs arr1[i][j] * arr2[i][j] ❌
  • Wrong dimensions → crash
  • Incorrect multiplication pattern

Problem 4: Diagonal Traverse — LeetCode​

1. Problem Summary​

  • Given an m x n matrix
  • Requirement: return elements in a zigzag diagonal order
  • Pattern: go diagonally up-right (↗), then down-left (↙), alternating

2. Approach​

Why this solution:

  • Option 1: Simulation (step by step)
  • Option 2: Group by diagonal (i + j) → easier to control
  • Choice: group and traverse by diagonal

Patterns applied:

  • Matrix traversal
  • Diagonal grouping
  • Zigzag traversal

Theory connection:

  • Key insight: i + j = const → same diagonal
  • Total diagonals: m + n - 1
  • Even diagonal → reverse; Odd diagonal → keep as-is

3. Solution Idea​

Traverse each diagonal k from 0 to m+n-2:

Find starting point:

if k < n:   i = 0,         j = k
else:        i = k - n + 1, j = n - 1

Traverse one diagonal:

while i < m and j >= 0:
    collect matrix[i][j]
    i++, j--

Handle zigzag:

if k % 2 == 0:
    reverse the collected diagonal

💡 Key Insight: "Group by i+j + alternate reversal"

4. Code​

class Solution:
    def findDiagonalOrder(self, mat):
        m, n = len(mat), len(mat[0])
        res = []

        for k in range(m + n - 1):
            temp = []

            # find starting point
            if k < n:
                i, j = 0, k
            else:
                i, j = k - n + 1, n - 1

            # traverse the diagonal
            while i < m and j >= 0:
                temp.append(mat[i][j])
                i += 1
                j -= 1

            # reverse if needed
            if k % 2 == 0:
                temp.reverse()

            res.extend(temp)

        return res

5. Complexity​

TypeComplexity
TimeO(m × n)
SpaceO(1)

5. Key Learnings​

Insight:

For diagonals in a matrix: i + j is the key.

Pattern reuse:

  • Diagonal Traverse II
  • Group diagonal
  • DP on diagonals
  • Zigzag traversal problems

Watch out for:

  • Forgetting to reverse → wrong zigzag
  • Wrong starting point (i, j)
  • Out of bounds when doing i++, j--
