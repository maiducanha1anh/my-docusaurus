Day1 - Prefix Sum 1D & 2D

Date: 11/4/2026 Topic: Prefix Sum 1D & 2D Total problems solved: 4

I. THEORY​

1. Definition​

Prefix Sum (cumulative sum array) is: A technique that pre-stores the sum of elements from the beginning up to index i

Prefix Sum 1D applies prefix sum to a 1-dimensional array prefix[i] = sum from start → i

a      = [1, 3, 5, 2, 4]
prefix = [1, 4, 9, 11, 15]

Prefix Sum 2D applies prefix sum to a matrix (2-dimensional) prefix[i][j] = sum from (0,0) → (i,j)

a = 1 2    →    prefix = 1 3
    3 4                   4 10

2. Core Idea​

Essence: Transform repeated sum calculations → into a single precomputation

Prefix Sum 1D

  • Store cumulative sum from start → i
  • Enables fast range sum query [l → r]

Prefix Sum 2D

  • Store cumulative sum from (0,0) → (i,j)
  • Enables fast sum query over any rectangular region

3. When to Use​

Recognition signal: If you see repeated sum calculations → immediately think Prefix Sum

Problem patterns:

  • "Calculate sum from l → r"
  • "Calculate sum of multiple segments"
  • "Calculate sum of a region in a matrix"
  • Multiple queries involved

Related patterns:

1D2D
Subarray sumSum of submatrix
Range sum queryGrid / map / image problems
Find subarray with sum = kGame map, heatmap

4. Complexity​

Prefix 1DPrefix 2D
BuildO(n)O(n × m)
QueryO(1)O(1)
SpaceO(n)O(n × m)

5. Common Pitfalls​

  • Confusing i and j: i = row, j = column
  • Misunderstanding 2D nature:
    • ❌ Thinking: prefix[i][j] is a single cell
    • ✅ Reality: it represents a region
  • Wrong 1D formula

II. PROBLEMS​

Problem 1: Running Sum of 1d Array​

Running Sum of 1d Array - LeetCode

1. Problem Summary​

  • Given an integer array nums
  • Create a new array (or modify in-place) such that each element at index i equals the sum of all elements from the beginning up to i

2. Approach​

  • Why this approach:
    • Traverse the array left to right
    • Keep track of the previous cumulative sum
    • Each step only needs to add the current element
    • Use array res to store intermediate results
  • Pattern applied: Prefix Sum 1D (1D cumulative sum) res[i] = res[i-1] + nums[i]
  • Theory connection: Belongs to Prefix Sum topic in DSA — reuse previous results to reduce complexity

3. Solution Idea​

  1. Create array res with the same size as nums
  2. Assign res[0] = nums[0]
  3. Iterate from i = 1 → n-1: res[i] = res[i-1] + nums[i]
  4. Return res

4. Code​

def runningSum(nums):
    res = [0] * len(nums)
    res[0] = nums[0]
    for i in range(1, len(nums)):
        res[i] = res[i-1] + nums[i]
    return res

5. Complexity​

  • Time Complexity: O(n) — single pass through the array
  • Space Complexity: O(n) — extra array res

6. Key Learning​

  • Insight: When the problem asks for "sum from start to i" → immediately think Prefix Sum
  • Pattern reuse: Range sum [l, r], count subarrays with sum equal to k
  • Notes:
    • Must handle the first element res[0] separately
    • Be careful with index (i-1)

Problem 2: Subarray Sum Equals K​

Subarray Sum Equals K - LeetCode

1. Problem Summary​

Given an integer array nums and an integer k, count the number of contiguous subarrays whose sum equals k.

2. Approach​

  • Why this approach:
    • Brute force all subarrays → O(n²) too slow
    • Need to optimize to O(n): use Prefix Sum + HashMap to avoid recomputation
  • Pattern applied: Prefix Sum + HashMap
  • Theory connection: Belongs to Prefix Sum topic in DSA

3. Solution Idea​

  1. Traverse the array left to right, compute cumulative sum currentSum
  2. Use HashMap to store prefixSum: number of occurrences
  3. At each step: check if currentSum - k exists in the map
  4. If yes → add the count to the result
  5. Update the map

4. Code​

def subarraySum(nums, k):
    count = 0
    currentSum = 0
    hashmap = {0: 1}

    for num in nums:
        currentSum += num
        if currentSum - k in hashmap:
            count += hashmap[currentSum - k]
        hashmap[currentSum] = hashmap.get(currentSum, 0) + 1

    return count

5. Complexity​

  • Time Complexity: O(n) — single pass through the array
  • Space Complexity: O(n) — HashMap storage

6. Key Learning​

  • Insight: When you see "subarray with sum = k" → immediately think: Prefix Sum + HashMap
  • Pattern reuse: Applicable to all Subarray Sum = k variants
  • Notes:
    • Must initialize map with {0: 1}
    • Array may contain negative numbers
    • HashMap stores frequency count, not just boolean

Problem 3: Range Sum Query 2D - Immutable​

Range Sum Query 2D - Immutable - LeetCode

1. Problem Summary​

Given a 2D matrix, handle multiple queries: calculate the sum of elements inside a rectangle defined by its upper-left corner (row1, col1) and lower-right corner (row2, col2).

2. Approach​

  • Why this approach:
    • Recomputing each query → O(m × n) too slow
    • Multiple queries → need optimization
    • Use 2D Prefix Sum: precompute once, query in O(1)
  • Pattern applied: 2D Prefix Sum
  • Theory connection: Prefix Sum 1D, Prefix Sum 2D

3. Solution Idea​

  1. Preprocessing: Create array dp of size (m+1) x (n+1), where dp[i][j] stores sum from (0,0) → (i-1, j-1)
  2. Answer query — apply the formula:
sum = dp[row2+1][col2+1]
    - dp[row1][col2+1]
    - dp[row2+1][col1]
    + dp[row1][col1]

4. Code​

class NumMatrix:
    def __init__(self, matrix):
        m, n = len(matrix), len(matrix[0])
        self.prefix = [[0] * (n + 1) for _ in range(m + 1)]

        for i in range(1, m + 1):
            for j in range(1, n + 1):
                self.prefix[i][j] = (matrix[i-1][j-1]
                                   + self.prefix[i-1][j]
                                   + self.prefix[i][j-1]
                                   - self.prefix[i-1][j-1])

    def sumRegion(self, row1, col1, row2, col2):
        p = self.prefix
        return (p[row2+1][col2+1]
              - p[row1][col2+1]
              - p[row2+1][col1]
              + p[row1][col1])

5. Complexity​

  • Time Complexity: O(1) per query
  • Space Complexity: O(m × n)

6. Key Learning​

  • Insight: When you see "multiple queries" + "region sum" → immediately think: Prefix Sum
  • Pattern reuse: Range Sum Query 1D / 2D, Image processing (region calculation)
  • Notes: Must use (m+1) x (n+1) array to avoid index out of bounds

Problem 4: 연속된 부분 수열의 합 (Sum of Contiguous Subsequence)​

Programmers - Sum of Contiguous Subsequence

1. Problem Summary​

  • Given a sorted (non-decreasing) array of integers and a number k
  • Find a contiguous subarray whose sum equals exactly k
  • If multiple subarrays qualify: choose the shortest one; if still tied → choose the one with the smallest starting index
  • Return [start index, end index]

2. Approach​

  • Why this approach:
    • Brute force → O(n²) too slow
    • All-positive array + sorted → Sliding Window is applicable
  • Pattern applied: Sliding Window / Two Pointers
  • Theory connection:
    • All-positive array, need to find subarray with sum = k
    • Use 2 pointers left, right to expand/shrink the window to control the sum

3. Solution Idea​

  1. Use 2 pointers: left = 0, right = 0, maintain currentSum
  2. Movement rules:
    • currentSum < k → expand (right++)
    • currentSum > k → shrink (left++)
    • currentSum == k → update result if better, then shift left to find shorter subarray
  3. Compare results by priority: 1. shorter length, 2. if equal → smaller left

4. Code​

def solution(sequence, k):
    left, right = 0, 0
    current_sum = sequence[0]
    result = [0, len(sequence) - 1]

    while right < len(sequence):
        if current_sum == k:
            if (right - left) < (result[1] - result[0]):
                result = [left, right]
            current_sum -= sequence[left]
            left += 1
        elif current_sum < k:
            right += 1
            if right < len(sequence):
                current_sum += sequence[right]
        else:
            current_sum -= sequence[left]
            left += 1

    return result

5. Complexity​

  • Time Complexity: O(n)
  • Space Complexity: O(1)

6. Key Learning​

  • Insight: All numbers are positive → sum always increases when expanding → Sliding Window works
  • Pattern reuse: Subarray sum = k (all positive), Longest/Shortest subarray
  • Notes:
    • Only use Sliding Window when there are no negative numbers
    • If negative numbers exist → must use Prefix Sum + HashMap
