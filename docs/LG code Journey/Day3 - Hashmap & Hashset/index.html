Day3 - Hashmap & Hashset

Date: 14/04/2026 Topic: HashMap & HashSet Total Problems Solved: 4

I. THEORY​

1. Definition​

HashMap (DSA) A data structure that maps: key → value, based on a Hash Table.

  • Primary goal: Access, insert, delete in O(1) (average)

HashSet (DSA) A collection of unique elements.

  • Essentially: HashSet = HashMap using only keys

2. Core Idea​

Hash Table = Array + Hash Function

Core formula: index = hash(key) % size

How it works:

StepDescription
Step 1: HashingConvert key → integer
Step 2: MappingMap to an index in the array
Step 3: Collision HandlingWhen 2 keys share the same index

Two main collision strategies:

  • Chaining (Linked List / Tree)
  • Open Addressing (less common in Java)

3. When to Use​

Indicators for HashMap:

  • "count", "frequency"
  • "fast lookup by value"
  • "check if already seen"

Related Patterns:

  1. Frequency Count
map.put(x, map.getOrDefault(x, 0) + 1);
  1. Two Sum
if (map.containsKey(target - x))
  1. Prefix Sum + HashMap — find subarray with sum k

Indicators for HashSet:

  • Check existence in O(1)
  • Remove duplicates
  • "longest consecutive sequence"

Related Patterns:

  1. Check duplicate
if (set.contains(x))

  1. Sliding Window + Set — substring with no repeating characters

  2. Graph / BFS visited

visited.add(node);

4. Complexity​

TypeComplexity
TimeO(n)
SpaceO(n)

5. Common Pitfalls​

  1. Assuming always O(1) — Wrong! That's only the average case
  2. Poor hash function → many collisions → severe performance degradation
  3. Forgetting to handle duplicates — especially in Two Sum, Sliding Window
  4. Using the wrong data structure
  5. High memory overhead — HashMap uses more memory than a plain array

II. PROBLEMS​

Problem 1: Unfinished Runner — Programmers​

1. Problem Summary​

Given 2 arrays:

  • participant: list of all participants
  • completion: list of those who finished

Conditions:

  • Exactly 1 person did not finish
  • Duplicate names are possible

Goal: Return the name of the person who did not finish.

2. Approach​

Why this solution:

  • N can be up to 100,000 → O(n²) nested loop will TLE
  • Need: count occurrences + fast comparison
  • → HashMap (frequency counting) is optimal

Patterns applied:

  • Frequency Count
  • HashMap Lookup O(1)

Theory connection:

  • HashMap: key = name, value = occurrence count
  • This is an extremely common pattern: Anagram, Two Sum (variant), Subarray Sum

3. Solution Idea​

Step 1: Count participants

leo  → 1
kiki → 1
eden → 1

Step 2: Subtract completions

eden → 0
kiki → 0
leo  → 1  ← answer

Step 3: Find the element with count ≠ 0

💡 Key Insight: Because names can be duplicated, a Set won't work — you must use a Map with counts.

4. Code​

def solution(participant, completion):
    hash_map = {}

    # count participants
    for p in participant:
        hash_map[p] = hash_map.get(p, 0) + 1

    # subtract completions
    for c in completion:
        hash_map[c] -= 1

    # find the person who did not finish
    for key in hash_map:
        if hash_map[key] != 0:
            return key

5. Complexity​

TypeComplexity
TimeO(n)
SpaceO(n)

6. Key Learnings​

Insight:

When you see "count", "compare frequencies", "has duplicates" → think HashMap (frequency counting)

Pattern reuse:

  • Two Sum (variant)
  • Valid Anagram
  • Subarray Sum = K
  • Longest Consecutive Sequence

Watch out for:

  1. Duplicates are the key point — using a Set will give wrong answers
  2. Avoid remove() on a list — it becomes O(n²)
  3. Remember: HashMap = O(1) lookup — extremely powerful in DSA

Problem 2: Phone Book — Programmers​

1. Problem Summary​

Given an array phone_book of phone numbers.

Goal: Check if any number is a prefix of another.

  • If a prefix exists → return false
  • If no prefix exists → return true

Example: "119" is a prefix of "1195524421" → false

2. Approach​

Why this solution:

  • N can be up to 1,000,000 → O(n²) will TLE
  • Need: fast prefix comparison

Patterns applied:

  1. String Prefix Matching — startsWith(), substring
  2. Sorting Trick (very clever): after sorting, prefixes are always adjacent

Theory connection:

  • Sorting + Greedy check
  • Hashing (alternative)
  • Trie (advanced)

3. Solution Idea​

Optimal approach: SORT

Step 1: Sort the array

["119", "1195524421", "97674223"]

Step 2: Compare adjacent elements

if (phone[i+1].startsWith(phone[i])) return false;

Why is this correct?

When sorted lexicographically, prefixes always appear next to their longer counterparts.

💡 Key Insight: No need to check all pairs — just check neighbors (i, i+1)

4. Code​

def solution(phone_book):
    phone_book.sort()

    for i in range(len(phone_book) - 1):
        if phone_book[i+1].startswith(phone_book[i]):
            return False

    return True

5. Complexity​

TypeComplexity
TimeO(n log n) sort + O(n) check
SpaceO(1) or O(n)

6. Key Learnings​

Insight:

When you see "prefix" or "string starts with" → think Sort + compare neighbors

Pattern reuse:

  • Longest Common Prefix
  • Detect prefix conflict
  • Dictionary / autocomplete
  • Trie problems

Watch out for:

  1. No need to compare every pair — only i and i+1
  2. Sort as strings, NOT as numbers — this is string prefix matching
  3. HashMap works too, but is more verbose and harder to optimize

Problem 3: Best Album — Programmers​

1. Problem Summary​

Given 2 arrays:

  • genres[i]: genre of song i
  • plays[i]: play count of song i

Goal: Build a "best album" following these rules:

  1. Select genres with higher total plays first
  2. Within each genre, pick at most 2 songs with the highest play counts
  3. If play counts are tied, prefer the lower index
  4. Return the list of selected song indices

2. Approach​

Why this solution:

  • N ≤ 10,000 → HashMap + Sorting is feasible
  • Need: group by genre, sort by multiple criteria
  • → HashMap + Sorting + Greedy

Patterns applied:

  1. Grouping — group by genre
  2. Frequency Aggregation — sum total plays per genre
  3. Custom Multi-criteria Sorting — sort by: total genre plays → individual plays → index

Theory connection:

  • HashMap (grouping + counting)
  • Multi-criteria sorting
  • Greedy selection
  • Pattern: Group + Sort + Top K

3. Solution Idea​

Two HashMaps needed:

Map 1: Total plays per genre

classic → 1450
pop     → 3100

Map 2: Song list per genre

classic → [(index, plays), ...]
pop     → [(index, plays), ...]

Steps:

  1. Build data — iterate all arrays, update total plays and song lists
  2. Sort genres by total plays descending: pop → classic
  3. For each genre, sort songs by: plays descending, then index ascending
  4. Pick top 2 songs from each genre

💡 Key Insight: This is NOT a simple HashMap problem — it's HashMap + multi-level sorting

4. Code​

def solution(genres, plays):
    from collections import defaultdict

    # 1. total plays per genre
    total = defaultdict(int)

    # 2. song list per genre
    songs = defaultdict(list)

    for i in range(len(genres)):
        g = genres[i]
        p = plays[i]
        total[g] += p
        songs[g].append((i, p))

    # 3. sort genres by total plays descending
    sorted_genres = sorted(total.keys(), key=lambda x: total[x], reverse=True)

    answer = []

    for g in sorted_genres:
        # sort songs within genre: plays desc, index asc
        songs[g].sort(key=lambda x: (-x[1], x[0]))

        # pick top 2
        for i, _ in songs[g][:2]:
            answer.append(i)

    return answer

5. Complexity​

TypeComplexity
TimeO(n log n)
SpaceO(n)

6. Key Learnings​

Insight:

When you see "group by category", "pick top K per group", "multiple sort criteria" → think HashMap + Sorting + Top K

Pattern reuse:

  • Top K Frequent Elements
  • Group Anagrams
  • Ranking system
  • Recommendation system

Watch out for:

  1. Multi-level sorting: plays ↓, then index ↑
  2. Must maintain 2 separate maps: total (aggregate) and songs (detail)
  3. Avoid brute force — it will TLE

Problem 4: Group Anagrams — LeetCode​

1. Problem Summary​

Given an array of strings strs.

Goal: Group all strings that are anagrams of each other.

Anagram: Same characters, different order (e.g., "eat", "tea", "ate")

Output example:

[["eat","tea","ate"], ["tan","nat"], ["bat"]]

2. Approach​

Why this solution:

  • Comparing every pair → O(n²) ❌ (TLE)
  • Need: quickly identify strings with the "same character structure"
  • → HashMap + normalized key

Patterns applied:

  1. Grouping with HashMap — key = group signature, value = list of elements
  2. Data Normalization — convert string to a canonical form
    • "eat" → "aet"
    • "tea" → "aet"

Theory connection:

  • Hashing (map key)
  • String normalization
  • Classification problem
  • Pattern: Group by Signature

3. Solution Idea​

Approach 1: Sort the String (most common)

Step 1: Create a HashMap

  • key = sorted string, value = list of anagrams

Step 2: Iterate each string

"eat" → "aet"
"tea" → "aet"  → push into the same group

Step 3: Return all values

💡 Key Insight: Anagrams always produce the same sorted string — this is the key trick.

Approach 2 (Advanced): Frequency Count

Instead of sorting, use a character frequency array as the key:

"aet" → [1,0,0,1,0,...,1,0,...]
  • O(k) instead of O(k log k) per string

4. Code​

from collections import defaultdict

class Solution:
    def groupAnagrams(self, strs):
        hashmap = defaultdict(list)

        for s in strs:
            key = ''.join(sorted(s))
            hashmap[key].append(s)

        return list(hashmap.values())

5. Complexity​

TypeComplexity
TimeO(n × k log k)
SpaceO(n × k)

(where k = average string length)

6. Key Learnings​

Insight:

When you see "group by property", "same structure", "rearrange" → think Normalize + HashMap

Pattern reuse:

  • Valid Anagram
  • Group Strings
  • Count characters problems
  • Bucket grouping

Watch out for:

  1. The key must normalize to the same value — use sorted string or frequency array
  2. Don't use a Set — you need to store multiple elements per group
  3. In Java: array keys won't work directly — must convert to String
  4. Sorting is costly — optimize with frequency count if needed
