Day4 - Stack & Monotonic Stack & Applications

Date: 15/04/2026 Topic: Basic Stack & Monotonic Stack Total Problems Solved: 4

I. THEORY​

📦 BASIC STACK​

1. Definition​

A Stack is a data structure that follows the LIFO principle: Last In, First Out.

Core operations:

OperationDescription
push(x)Add an element to the top
pop()Remove the top element
top() / peek()View the top element without removing

2. Core Idea​

Stack is used for:

  • Storing temporary state
  • Backtracking (light reverse tracing)
  • Processing in reverse order

Essence: Only care about the nearest element (top)

3. When to Use​

Indicators:

  • Problems involving: "nearest", "previous", "go back"
  • Problems with brackets ()[]{} → validity check
  • Undo / Redo
  • Expression evaluation

Related Patterns:

  • Parentheses Matching
  • Expression Evaluation
  • Simple Backtracking
  • DFS (using stack instead of recursion)

4. Complexity​

TypeComplexity
Time (per operation)O(1)
SpaceO(n)

📈 MONOTONIC STACK​

1. Definition​

A Monotonic Stack is a stack where elements are always in strictly increasing or strictly decreasing order.

Two types:

  • Increasing Stack — elements increase from bottom to top
  • Decreasing Stack — elements decrease from bottom to top

2. Core Idea​

Key Principle: Keep elements that are "potentially useful in the future" and discard those that are "no longer relevant."

How it works: When adding a new element:

  1. Pop all elements that no longer have value
  2. Push the new element

💡 Simple mental model: "If an old element can never be the answer → remove it immediately"

3. When to Use​

Indicators:

  • "Nearest Greater Element"
  • "Next Smaller Element"
  • "Previous Greater Element"
  • Finding the nearest larger/smaller element

Problem types:

  • Histogram (Largest Rectangle)
  • Stock span
  • Sliding window (combined with deque)

Related Patterns:

  • Next Greater Element (NGE)
  • Previous Smaller Element (PSE)
  • Largest Rectangle in Histogram
  • Daily Temperatures (LeetCode)

4. Complexity​

TypeComplexity
TimeO(n)
SpaceO(n)

5. Common Pitfalls​

  1. Confusing which type of stack to use (increasing vs decreasing)
  2. Wrong pop condition
  3. Not understanding "what to keep" in the stack
  4. Confusing index vs value

II. PROBLEMS​

Problem 1: Valid Parentheses — Programmers​

1. Problem Summary​

Given a string containing only '(' and ')'.

Goal: Check whether the string is valid.

A string is valid when:

  • Every ( has a matching )
  • The order is correct (no inversions)

Examples:

"()"    → True
"(())"  → True
"(()"   → False
")("    → False

2. Approach​

Why this solution:

  • Keywords: "nearest pair", "correct open/close order" → Stack pattern

Patterns applied:

  • Stack
  • Parentheses Matching
  • LIFO (Last In First Out)

Theory connection:

  • When encountering ) → need to check the nearest ( before it
  • This is exactly the behavior of a stack (top)

3. Solution Idea​

Approach 1: Stack (standard DSA)

1. Create an empty stack
2. Iterate each character:
   - If '(' → push onto stack
   - If ')':
       - If stack is empty → invalid immediately
       - Otherwise → pop
3. After iteration:
   - Stack empty   → valid ✅
   - Stack not empty → invalid ❌

Approach 2: Optimized (no stack needed)

Since there is only 1 type of bracket, use a counter:

'(' → count + 1
')' → count - 1

Rule:
  If count < 0 → invalid (closing before opening)
  At the end:
    count == 0 → valid ✅
    count != 0 → invalid ❌

4. Code​

def solution(s):
    count = 0

    for ch in s:
        if ch == '(':
            count += 1
        else:
            count -= 1

        if count < 0:
            return False

    return count == 0

5. Complexity​

TypeComplexity
TimeO(n)
SpaceO(n)

6. Key Learnings​

Insight:

You don't always need a stack. If there's only 1 type of bracket → a counter is sufficient.

When to use which:

  • "()" only → use counter
  • "()[]{}" → must use stack

Watch out for:

  • Most critical case: ")(" → negative count must return False immediately
  • Common mistake: only checking the total count of brackets (wrong!)
  • Not checking count < 0 during traversal

Problem 2: Stock Prices — Programmers​

1. Problem Summary​

Given an array prices where prices[i] is the stock price at time i.

Goal: For each time i, find how many seconds the price does NOT drop.

In other words: at each i, find how many steps forward until encountering a lower price.

Example:

prices = [1, 2, 3, 2, 3]
output = [4, 3, 1, 1, 0]

Price 3 (index 2) → drops after 1 step → output = 1

2. Approach​

Why this solution:

  • Problem pattern: "when does it drop?", "next smaller element"
  • This is a classic Next Smaller Element problem

Patterns applied:

  • Monotonic Stack (decreasing)
  • Next Smaller Element
  • Stack storing indices

Theory connection:

  • When we see a smaller element → we "resolve" all previous elements in the stack
  • Stack stores: indices of elements that haven't been answered yet

3. Solution Idea​

Core thinking:

If a new price is lower than a previous price → that previous price "ends its waiting period"

Algorithm:

answer = [0] * n
stack = []  # stores indices

for i in range(n):
    while stack and prices[i] < prices[stack[-1]]:
        idx = stack.pop()
        answer[idx] = i - idx
    stack.append(i)

# Remaining elements in stack → price never dropped
while stack:
    idx = stack.pop()
    answer[idx] = n - idx - 1

4. Code​

def solution(prices):
    n = len(prices)
    answer = [0] * n
    stack = []

    for i in range(n):
        while stack and prices[i] < prices[stack[-1]]:
            idx = stack.pop()
            answer[idx] = i - idx

        stack.append(i)

    while stack:
        idx = stack.pop()
        answer[idx] = n - idx - 1

    return answer

5. Complexity​

TypeComplexity
TimeO(n)
SpaceO(n)

6. Key Learnings​

Insight:

Classic monotonic stack problem. No need for repeated traversal → optimized from O(n²) to O(n).

Pattern reuse:

  • Next Smaller Element
  • Next Greater Element
  • Daily Temperatures
  • Largest Rectangle in Histogram

Watch out for:

  1. Forgetting to handle remaining stack elements → wrong output
  2. Using value instead of index → can't calculate distance
  3. Wrong comparison sign — prices[i] < prices[stack[-1]]: wrong sign = wrong logic
  4. Brute force O(n²) may pass small inputs, but the goal here is the stack approach

Problem 3: Daily Temperatures — LeetCode​

1. Problem Summary​

Given an array temperatures where temperatures[i] is the temperature on day i.

Goal: For each day, find how many days until a warmer temperature. If no warmer day exists → return 0.

Example:

Input:  [73, 74, 75, 71, 69, 72, 76, 73]
Output: [1,  1,  4,  2,  1,  1,  0,  0]

2. Approach​

Why this solution:

  • Problem pattern: "find the nearest larger element to the right"
  • This is exactly: Next Greater Element (NGE)

Patterns applied:

  • Monotonic Stack (decreasing)
  • Next Greater Element
  • Stack storing indices

Theory connection:

  • Stack holds elements that haven't found a warmer day yet
  • When a higher temperature is encountered → resolve all previous stack entries

3. Solution Idea​

Core thinking:

If today is hotter than a previous day → that previous day now "has its answer"

Algorithm:

# Step 1: Initialize
answer = [0] * n
stack = []  # stores indices

# Step 2: Traverse left → right
for i in range(n):
    # Step 3: Found a warmer day
    while stack and temperatures[i] > temperatures[stack[-1]]:
        idx = stack.pop()
        answer[idx] = i - idx  # Step 4: Calculate distance

    stack.append(i)  # Step 4: Push current index

# Step 5: Remaining elements → no warmer day → keep 0

4. Code​

class Solution:
    def dailyTemperatures(self, temperatures):
        n = len(temperatures)
        answer = [0] * n
        stack = []

        for i in range(n):
            while stack and temperatures[i] > temperatures[stack[-1]]:
                idx = stack.pop()
                answer[idx] = i - idx

            stack.append(i)

        return answer

5. Complexity​

TypeComplexity
TimeO(n)
SpaceO(n)

6. Key Learnings​

Insight:

This is the standard template for monotonic stack: "When encountering a greater element → process the stack"

Pattern reuse:

  • Stock Prices (previous problem)
  • Next Greater Element
  • Next Smaller Element (flip the sign)
  • Largest Rectangle in Histogram
  • Daily Temperatures (this problem)

Watch out for:

  1. Wrong comparison sign — this problem uses > (greater); wrong sign = wrong logic
  2. Not using index → can't compute distance
  3. Forgetting while → must process multiple consecutive elements
  4. Thinking brute force is enough — O(n²) → TLE for n = 10⁵

Problem 4: Largest Rectangle in Histogram — LeetCode​

1. Problem Summary​

Given an array heights where each element is the height of a histogram bar (each bar has width = 1).

Goal: Find the largest rectangle that can be formed from consecutive bars.

Example:

heights = [2, 1, 5, 6, 2, 3]
output  = 10

Best rectangle: height = 5, width = 2 → area = 10

2. Approach​

Why this solution:

  • The problem requires: expanding left + right, bounded by shorter bars
  • This is a Previous Smaller + Next Smaller Element problem

Patterns applied:

  • Monotonic Stack (increasing)
  • Next Smaller Element (NSE)
  • Previous Smaller Element (PSE)

Theory connection:

  • For each bar i, find:
    • Left boundary: nearest shorter bar to the left
    • Right boundary: nearest shorter bar to the right
  • Area formula:
area = heights[i] × (right - left - 1)

3. Solution Idea​

💡 Most important insight: "Each bar is the height of one rectangle"

Optimal approach — Monotonic Stack (increasing):

  • Stack stores indices, maintaining increasing order

Algorithm:

# Step 1: Add sentinels to handle edge cases
heights = [0] + heights + [0]

stack = []

for i in range(len(heights)):
    # Step 3: Found a shorter bar → can't expand further
    while stack and heights[i] < heights[stack[-1]]:
        h = heights[stack.pop()]        # Step 4: Height of rectangle
        w = i - stack[-1] - 1           # Step 4: Width of rectangle
        area = h * w
        max_area = max(max_area, area)

    stack.append(i)                     # Step 5: Push index

💡 Key Insight: When a shorter bar is encountered → "close the rectangle" of all previous taller bars

4. Code​

class Solution:
    def largestRectangleArea(self, heights):
        stack = []
        max_area = 0

        heights = [0] + heights + [0]

        for i in range(len(heights)):
            while stack and heights[i] < heights[stack[-1]]:
                h = heights[stack.pop()]
                w = i - stack[-1] - 1
                max_area = max(max_area, h * w)

            stack.append(i)

        return max_area

5. Complexity​

TypeComplexity
TimeO(n)
SpaceO(n)

6. Key Learnings​

Insight:

This is the pinnacle of monotonic stack problems. The stack efficiently determines left + right boundaries in O(n).

Pattern reuse:

  • Next Smaller Element
  • Daily Temperatures (flip sign)
  • Stock Prices
  • Trapping Rain Water
  • Maximal Rectangle (2D version)

Watch out for:

  1. Wrong width formula — correct: w = i - stack[-1] - 1
  2. Forgetting sentinels [0] + heights + [0] → stack won't be fully processed
  3. Confusing increasing vs decreasing stack — this problem uses an increasing stack
  4. Misunderstanding the stack's purpose — it doesn't store everything, only valid candidates
