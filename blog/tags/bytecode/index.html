Tìm hiểu Java Platform – Execution Flow & JVM Architecture

November 2, 2026 · 5 min read
Mai Duc Anh
Blogger & Developer

1. Java Platform Overview – Tổng quan nền tảng Java​

Java không chỉ là một ngôn ngữ lập trình, mà là một nền tảng hoàn chỉnh (Java Platform).

👉 Khi nói “lập trình Java”, thực chất ta đang làm việc với 3 thành phần cốt lõi:

  • Java Language
  • JVM (Java Virtual Machine)
  • Hệ sinh thái thư viện & công cụ

Mục tiêu cốt lõi của Java​

Write Once, Run Anywhere (WORA)

Viết code một lần, chạy được trên:

  • Windows
  • Linux
  • macOS
    … mà không cần sửa code

2. Vai trò của JDK, JRE, JVM​

Rất nhiều người học Java bị nhầm lẫn 3 khái niệm này, nên cần làm rõ tuyệt đối.

2.1 JVM – Java Virtual Machine​

JVM là gì?

  • JVM là máy ảo
  • Chạy bytecode Java
  • Đóng vai trò trung gian giữa Java và hệ điều hành

📌 JVM:

  • Không hiểu .java
  • Không hiểu .exe
  • Chỉ hiểu .class (bytecode)

👉 Mỗi hệ điều hành có JVM riêng, nhưng:

  • Bytecode thì giống nhau

2.2 JRE – Java Runtime Environment​

JRE gồm:

  • JVM
  • Core Java Libraries (java.lang, java.util, ...)
  • Các file cấu hình runtime

👉 JRE dùng để:

  • Chạy chương trình Java
  • ❌ Không dùng để viết hay biên dịch code

📌 Nếu máy chỉ có JRE:

  • Chạy được .class
  • ❌ Không biên dịch được .java

2.3 JDK – Java Development Kit​

JDK = JRE + Công cụ phát triển

Bao gồm:

  • javac (compiler)
  • java (launcher)
  • javadoc, jdb, ...

👉 JDK dùng để:

  • Viết code
  • Biên dịch
  • Chạy
  • Debug

📌 Khi cài Java để học lập trình: ➡️ LUÔN cần JDK

2.4 Mối quan hệ tổng thể​

JDK
├── JRE
│ ├── JVM
│ └── Java Core Libraries
└── Development Tools

3. Mối quan hệ giữa Java Language và Java Platform​

Java Language​

  • Cú pháp và từ khóa
  • Kiểu dữ liệu
  • OOP (class, object, inheritance)
  • File mã nguồn .java

Java Platform​

  • JVM (Java Virtual Machine)
  • ClassLoader Subsystem
  • Runtime Data Areas
  • Execution Engine & Garbage Collector

Java Language chỉ là phần nổi
Java Platform mới là thứ quyết định chương trình chạy thế nào

4. Java Execution Flow – Luồng thực thi của Java​

Khi bạn chạy một chương trình Java, JVM không thực thi trực tiếp file .java.

Luồng tổng quát​

IDE
↓ (Save)
Hello.java (Ổ cứng)
↓ (Compile)
javac Hello.java
↓
Hello.class (Bytecode)
↓
JVM (RAM)
↓
OS
↓
CPU thực thi

5. Compile-time và Runtime trong Java​

5.1 Compile-time​

Xảy ra khi chạy:

javac Hello.java

Đầu vào:

File .java (source code)

Java làm gì? -Kiểm tra cú pháp -Kiểm tra kiểu dữ liệu -Biên dịch sang bytecode

Đầu ra: -File .class

📌 Compile-time không chạy chương trình

5.2 Runtime​

Xảy ra khi chạy:

java Hello

Đầu vào: -File .class

Java làm gì? -JVM load class -Kiểm tra bytecode

Thực thi 📌 Runtime mới là lúc chương trình thực sự chạy

6. Bytecode là gì? Vì sao Java portable?​

Bytecode là gì? -Là mã trung gian -Không phải mã máy -Không phụ thuộc OS hay CPU

📌 Bytecode: -Chạy trên JVM -JVM dịch tiếp sang mã máy

Vì sao Java chạy đa nền tảng?

Java Source (.java)
↓
Bytecode (.class)
↓
┌─────────────┐
│ JVM Windows │ → CPU Windows
│ JVM Linux │ → CPU Linux
│ JVM macOS │ → CPU macOS
└─────────────┘

👉 Không phải Java chạy trực tiếp trên OS 👉 JVM mới là thứ chạy trên OS

7. JVM Architecture – Kiến trúc JVM​

JVM gồm 3 khối lớn: -ClassLoader Subsystem -Runtime Data Areas -Execution Engine

8. ClassLoader Subsystem​

Nhiệm vụ: -Load .class vào JVM -Kiểm tra tính hợp lệ -Chuẩn bị class để chạy

Các loại ClassLoader trong JVM​

  • Bootstrap ClassLoader
    Load các core class của Java (ví dụ: java.lang, java.util)

  • Platform ClassLoader (Java 9+)
    Load các thư viện thuộc Java Platform (ví dụ: java.sql, java.xml)

  • Application ClassLoader
    Load các class do lập trình viên viết (classpath) 📌 Class chỉ được load khi cần thiết

9. Runtime Data Areas – Vùng nhớ trong JVM​

9.1 Method Area​

Lưu: -Class metadata -Method info -Static variables

9.2 Heap​

-Lưu object -Dùng chung cho toàn JVM -Do Garbage Collector quản lý

9.3 Stack​

Mỗi thread có stack riêng

Lưu: -Local variables -Method call -Reference

📌 Stack nhỏ, nhanh 📌 Heap lớn, chậm hơn

9.4 PC Register​

Lưu địa chỉ instruction đang chạy

9.5 Native Method Stack​

Dùng cho code native (C/C++)

10. Execution Engine – Bộ máy thực thi​

10.1 Interpreter​

Đọc bytecode

Thực thi từng instruction

📌 Ưu điểm: -Chạy ngay

📌 Nhược điểm: -Chậm nếu chạy lặp nhiều lần

10.2 JIT Compiler (Just-In-Time)​

JIT làm gì? -Phát hiện đoạn code chạy nhiều -Biên dịch bytecode → mã máy -Cache lại để dùng sau

📌 JVM hiện đại: -Interpreter + JIT -Tự tối ưu khi chương trình chạy

Phân tích cơ chế hoạt động của JVM qua đoạn code cụ thể

February 22, 2026 · 6 min read
Mai Duc Anh
Blogger & Developer

Trong bài viết này, chúng ta sẽ phân tích toàn bộ cơ chế hoạt động của JVM khi thực thi đoạn code sau:

class Student {
    int age;
}

public class Main {
    public static void main(String[] args) {
        Student s1 = new Student();
        s1.age = 20;

        Student s2 = s1;
        s2.age = 25;

        int x = 10;
        int y = x;

        System.out.println("s1.age = " + s1.age);
        System.out.println("s2.age = " + s2.age);
        System.out.println("x = " + x);
        System.out.println("y = " + y);
    }
}

I. ĐẦU VÀO VÀ ĐẦU RA CỦA JVM ?​

ĐẦU VÀO
Khi chạy:

java Main

JVM nhận đầu vào là:

  • File Main.class
  • File Student.class
  • Bytecode bên trong các file này

⚠️ Lưu ý: JVM không chạy source code .java, mà chạy bytecode trong .class.

ĐẦU RA

  • Console output
  • Thay đổi trạng thái bộ nhớ
  • Object được tạo trong Heap
  • Stack Frame được push/pop

Console in ra:

s1.age = 25
s2.age = 25
x = 10
y = 10

II. CLASS LOADER SUBSYSTEM​

1, Loading

Application ClassLoader load:

  • Main.class
  • Student.class
  • Metadata của các class được đưa vào Method Area (Metaspace).

2, Linking

Gồm 3 bước:

✔ Verify

  • Kiểm tra bytecode có hợp lệ không
  • Không tràn stack
  • Không truy cập sai kiểu dữ liệu

✔ Prepare

  • Cấp phát bộ nhớ cho static field (nếu có)
  • Gán giá trị mặc định

✔ Resolve

  • Chuyển symbolic reference → direct reference Giải thích thêm phần resolve có symbolic reference nó chỉ là thông tin dạng chữ

irect reference là: -Con trỏ (pointer) thật

  • Hoặc offset trong Method Area -Hoặc địa chỉ method trong runtime

3, Initialization

  • Chạy static block (nếu có)
  • Khởi tạo static variable

Sau giai đoạn này

Trong Method Area có:

Class Student
  field: age
  constructor

Class Main
  method: main()
  bytecode
  constant pool

⚠️ Chưa có object nào trong Heap.

III. 16 BƯỚC RUNTIME THEO JAVA VISUALIZER​

STEP 1 — JVM khởi tạo process

Tại sao có main:7?

  • JVM không biết “dòng 7”
  • JVM chỉ biết bytecode index
  • main:7 là do Java Visualizer map bytecode → source line

PC Register trỏ tới bytecode đầu tiên của method main. Công cụ hiển thị nó thành main:7 vì đó là dòng source tương ứng.

Hệ điều hành tạo một PROCESS mới

Process này chứa:

  • Heap
  • Method Area
  • Stack
  • PC Register
  • Native Method Stack

Đây gọi là JVM Runtime Data Areas

ClassLoader bắt đầu hoạt động

JVM không chạy ngay main.

Nó phải:

  • Load class Main
  • Load class Student

Cơ chế: Application ClassLoader sẽ:

  • Đọc file Main.class
  • Đưa bytecode vào Method Area

STEP 2 — Tạo Main Thread

JVM tạo:

  • Main Thread
  • Stack cho thread (Mỗi thread có một Stack riêng, và JVM tạo một Stack Frame)
  • Frame main()

Tại sao có main:7?

  • Vì dòng 7 là lệnh đầu tiên trong main

STEP 3 — new Student()

JVM gặp new Student().

  • JVM cấp phát một object trong Heap
  • Field age được gán mặc định = 0

Stack lúc này:

  • Vẫn chỉ có frame main().

frames <init> : 1 nghĩa là frame 1 this : là object trên heap

STEP 4 — Gọi constructor

JVM tạo Frame mới:

STEP 5 — Constructor return

Sau đó constructor kết thúc → Frame <init> bị pop.

STEP 6 — Gán cho s1

  • Nhưng operand stack chứa reference trả về từ new.
  • Sau đó reference được lưu vào biến s1.

STEP 7 — s1.age = 20

JVM làm gì?

  • Tìm reference s1 trong Stack
  • Theo địa chỉ sang Heap
  • Tìm field age
  • sửa giá trị = 20

STEP 8 — Student s2 = s1

JVM KHÔNG tạo object mới.

Nó chỉ:

  • Copy giá trị reference của s1
  • Gán cho s2

=> s1 và s2 trỏ cùng 1 object.

STEP 9 — s2.age = 25

JVM:

  • Lấy reference từ s2
  • Trỏ tới object trong Heap
  • Đổi age = 25

Vì s1 và s2 cùng trỏ một object → cả hai đều thấy age = 25

STEP 10 - int x = 10

Primitive lưu trực tiếp trong Stack Frame x = 10

Heap không thay đổi

STEP 11 — int y = x

Đây là Copy giá trị y = 10 vì y = x

Không có reference ở đây

STEP 12 — Chuẩn bị println đầu tiên

JVM làm:

-Lấy dữ liệu từ Stack hoặc Heap

  • Đẩy vào operand stack
  • Gọi phương thức println()

STEP 13 — Gọi println()

Tương tự bước 12

STEP 14 — println x

  • Lấy x từ stack
  • Giá trị = 10

STEP 15 — println y

  • Lấy x từ stack
  • Giá trị = 10

STEP 16 — main() kết thúc

Stack lúc gọi println: Frame println() Frame main()

Khi in xong:

  • Frame println() bị pop.

Stack rỗng.

Object trong Heap không còn reference.

  • Garbage Collector sẽ dọn sau.

IV. TỔNG KẾT BỘ NHỚ​

Thành phầnLưu gì
Method AreaMetadata, bytecode, constant pool
HeapObject
StackPrimitive + Reference
PC RegisterVị trí bytecode hiện tại

V. Kết luận​

Tham khảo slide chi tiết tại đây :

Cốt lõi cần nắm :

  • Object luôn nằm trong Heap
  • Reference nằm trong Stack
  • Primitive nằm trong Stack
  • Method call → tạo Stack Frame
  • Constant Pool lưu symbolic reference
  • Execution Engine đọc bytecode
  • GC dọn object khi không còn reference

Qua ví dụ đơn giản này, ta thấy:

JVM không chỉ “chạy code”, mà:

  • Load class
  • Xác minh bytecode
  • Quản lý bộ nhớ
  • Thực thi theo kiến trúc stack
  • Gọi native code
  • Thu gom rác tự động

Hiểu rõ cơ chế này giúp ta:

  • Tránh memory leak
  • Hiểu reference vs primitive
  • Hiểu vì sao GC hoạt động
  • Debug vấn đề liên quan tới JVM sâu hơn
