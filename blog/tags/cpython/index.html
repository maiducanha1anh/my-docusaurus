Understanding Python – From Overview to Internal Mechanisms

February 2, 2026 · 5 min read
Mai Duc Anh
Blogger & Developer

1. General Overview of Python​

Python is a high-level programming language created by Guido van Rossum, first officially released in 1991. Python was designed with the philosophy of being simple, readable, easy to learn, and easy to maintain, allowing developers to focus more on business logic rather than complex syntax.

Key Features of Python​

  • Syntax close to natural language, highly readable
  • Multi-purpose language: Web, AI, Data Science, Automation, Game development, IoT
  • Rich ecosystem of libraries (NumPy, Pandas, TensorFlow, Django, Flask, ...)
  • Cross-platform: Windows, Linux, macOS
  • Large community, extensive documentation

Python is especially well-suited for:

  • IT students
  • Beginners in programming
  • Systems that require rapid development

2. Interpreted vs Compiled – Execution Mechanisms​

When discussing how a language is executed, we typically distinguish between two concepts: Compiled and Interpreted.

Compiled Language​

Examples: C, C++, Go

Workflow:

Source Code (.c)
↓
Compiler
↓
Machine Code (.exe)

Characteristics:

  • Compiles the entire program before execution
  • Fast execution, high performance
  • Platform and CPU architecture dependent
  • Harder to debug

Interpreted Language​

Examples: Python, JavaScript, PHP

Workflow:

Source Code (.py)
↓
Interpreter
↓
Line-by-line execution

Characteristics:

  • No need to produce an .exe file
  • Easier to debug, easier to learn
  • Generally slower than compiled languages

⚠️ Python is not purely interpreted – this will become clearer when we look at CPython.

3. Python's Execution Workflow – From Source Code to Running Program​

When you run a Python file (file.py), Python does not execute the source code directly.

General Workflow​

IDE
↓ (Save)
file.py (Disk)
↓ (Run)
Source Code (RAM)
↓
Lexical Analysis → Tokens (RAM)
↓
Parsing → AST (RAM)
↓
Compile
↓
Bytecode (RAM + optionally written as .pyc to disk)
↓
Python Virtual Machine (RAM)
↓
CPU execution

Detailed Breakdown​

Stage 1: Python reads file.py into memory (Python Source Code → RAM)

When you run:

python main.py

Input:

  • file.py
  • Location: disk

What Python does:

  • The OS reads the contents of file.py
  • Loads the entire source code into RAM
  • Converts code into a character string (text)

Output:

  • Python source code resides in RAM
  • file.py remains on disk, unmodified

📌 From this point on:

Python only operates on the code in RAM

The disk serves only as storage

Stage 2: Lexical Analysis & Parsing (Source Code → AST)

2.1 Lexical Analysis

Input:

  • Source code (text) in RAM

Example:

a = 10

What Python does:

Breaks code into tokens:

a → IDENTIFIER

= → OPERATOR

10 → NUMBER

📌 At this stage:

Python does not yet understand the logic

It only recognizes "symbols"

2.2 Parsing

Input:

  • Token stream (RAM)

What Python does:

  • Validates syntax correctness
  • Builds an Abstract Syntax Tree (AST)

Example:

a = 10

→ AST represents:

  • Assign value 10 to variable a

Output:

  • AST
  • Resides in RAM

❌ If syntax is invalid → SyntaxError (execution stops here)

Stage 3: Compilation to Bytecode (AST → Bytecode .pyc)

Input:

  • AST (RAM)

What Python does:

  • Compiles the AST into Bytecode

Bytecode is:

  • An intermediate representation

  • Not machine code

  • Platform-independent

Output:

  • Bytecode

  • Resides in RAM

Additionally:

  • Python may write bytecode to disk

  • As a .pyc file inside the __pycache__ directory

📌 Important:

.pyc is not always generated

It is used to:

  • Speed up subsequent runs

  • Avoid recompilation if the source code hasn't changed

Stage 4: Python Virtual Machine (PVM) (Bytecode → Execution)

Input:

  • Bytecode (RAM)

What Python does:

  • Python Virtual Machine:

  • Reads each instruction in the bytecode

  • Executes them sequentially

  • Each instruction:

  • Calls the corresponding C function in CPython

  • The CPU executes the real instruction

Output:

  • The program runs

  • Creates variables and objects in the heap

  • Prints to screen, writes files, calls APIs, etc.

📌 Critical note:

  • PVM runs in RAM

  • The CPU does not execute Python source code

  • The CPU only executes the machine code of CPython

➡️ This is why Python is commonly described as:

"An interpreted language with a compilation step"

4. What is CPython and Why Does It Matter?​

CPython​

CPython is the most widely used implementation of Python, written in C.

👉 When you download Python from python.org, you are using CPython.

Role of CPython​

  • Compiles Python code → Bytecode
  • Executes bytecode via the PVM
  • Manages memory
  • Provides an API for C Extensions

Other Python Implementations​

  • PyPy: uses JIT compilation, can be faster than CPython
  • Jython: runs on the JVM
  • IronPython: runs on .NET

➡️ However, CPython remains the de facto standard.

5. How Does Python Manage Memory?​

Python manages memory automatically; developers do not need to manually allocate or free memory.

Main Memory Regions​

  1. Stack Memory

    • Stores local variables
    • Manages function calls

  2. Heap Memory

    • Stores objects (list, dict, class instances, …)
    • Managed by CPython

Every Python Object Consists of​

  • Value
  • Data type
  • Reference count (number of active references)

6. Garbage Collection in Python​

Reference Counting​

Python uses reference counting as its primary memory management mechanism.

  • Each object tracks its reference count
  • When the count reaches 0 → the object is deallocated

Example:

a = []
b = a

del a
del b  # only at this point is the list object actually freed

7. Summary​

  • 🔗 https://www.canva.com/design/DAG_3zWkweQ/ZLs9aa_VVotSC-yXgsAZOw/edit

Python is a language with clean syntax that is easy to learn, yet internally operates through a relatively complex set of mechanisms. When running a Python program, source code is not executed directly — it goes through multiple stages including lexical analysis, parsing, compilation to bytecode, and execution via the Python Virtual Machine (PVM).

Python is not a purely interpreted language; it is better described as an interpreted language with an intermediate compilation step. CPython plays a central role in compilation, execution, and memory management. Thanks to automatic memory management and Garbage Collection, Python lets developers focus on logic rather than resource handling.

Understanding Python's internal workflow and mechanisms enables developers to write more efficient code, debug more effectively, and build a solid foundation for working with Python in large-scale systems.
