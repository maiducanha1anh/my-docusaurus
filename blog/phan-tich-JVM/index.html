Phân tích cơ chế hoạt động của JVM qua đoạn code cụ thể

February 22, 2026 · 10 min read
Mai Duc Anh
Blogger & Developer

Trong bài viết này, chúng ta sẽ phân tích toàn bộ cơ chế hoạt động của JVM khi thực thi đoạn code sau:

class Student {
    int age;
}

public class Main {
    public static void main(String[] args) {
        Student s1 = new Student();
        s1.age = 20;

        Student s2 = s1;
        s2.age = 25;

        int x = 10;
        int y = x;

        System.out.println("s1.age = " + s1.age);
        System.out.println("s2.age = " + s2.age);
        System.out.println("x = " + x);
        System.out.println("y = " + y);
    }
}

I. ĐẦU VÀO VÀ ĐẦU RA CỦA JVM ?​

ĐẦU VÀO
Khi chạy:

java Main

JVM nhận đầu vào là:

  • File Main.class là file được biên dịch từ file Main.java

  • File Student.class là file được biên dịch từ file Main.java

  • Bytecode (Bytecode là mã trung gian được tạo ra sau khi compile file .java, và được JVM thực thi.) bên trong các file này

⚠️ Lưu ý: JVM(là máy ảo thực thi chương trình java) không chạy source code .java, mà chạy bytecode trong .class.

ĐẦU RA

  • Console output(kết quả đầu ra )

  • Thay đổi trạng thái bộ nhớ
  • Object( là một thực thể được tạo ra từ một class) được tạo trong Heap(là vùng nhớ trong JVM dùng để lưu trữ object.)
  • Stack Frame(Stack Frame là một khối dữ liệu được tạo ra mỗi khi một method được gọi.Nó nằm trong Java Stack của từng thread) được push/pop

Console in ra:

s1.age = 25
s2.age = 25
x = 10
y = 10

II. CLASS LOADER SUBSYSTEM (Là bộ phận của JVM chịu trách nhiệm nạp file .class vào bộ nhớ và chuẩn bị cho việc thực thi.)​

1, Loading(Quá trình đọc file .class và đưa nó vào bộ nhớ JVM.)

Application ClassLoader load:

  • Main.class
  • Student.class
  • Metadata của các class được đưa vào Method Area .

Method Area là Vùng nhớ dùng để lưu thông tin class đã được load. gồm:

  • Bytecode của method
  • Metadata của class
  • Runtime Constant Pool
  • Static variables

Metadata là dữ liệu mô tả class. gồm:

  • tên class: Student
  • Superclass: Object
  • Danh sách field
  • Danh sách method -Access modifier

2, Linking (là bước kiểm tra an toàn)

Gồm 3 bước:

✔ Verify(Kiểm tra bytecode có hợp lệ và an toàn không.)

  • Kiểm tra bytecode có hợp lệ không
  • Không tràn stack
  • Không truy cập sai kiểu dữ liệu

✔ Prepare(Cấp phát bộ nhớ cho static variables và gán giá trị mặc định.)

  • Cấp phát bộ nhớ cho static field (nếu có)
  • Gán giá trị mặc định

✔ Resolve(Chuyển symbolic reference thành direct reference.)

  • Chuyển symbolic reference → direct reference Giải thích thêm phần resolve
  • symbolic reference nó chỉ là thông tin dạng chữ
  • direct reference là địa chỉ method trong runtime

3, Initialization(Khởi tạo)

  • Chạy static block(Static block là một khối lệnh được thực thi một lần duy nhất khi class được load lần đầu.) (nếu có)
  • Khởi tạo static variable(là 1 bộ phận nằm trong method Area)

Sau giai đoạn này

Trong Method Area có:

Class Student
  field: age
  constructor

Class Main
  method: main()
  bytecode
  constant pool

constant pool là gì

  • Constant Pool là một bảng chứa tất cả các “hằng số” và “thông tin ký hiệu (symbolic reference)” mà class đó sử dụng.
  • Nó nằm bên trong file .class.

Constructor là hàm đặc biệt của class, được dùng để khởi tạo object khi ta tạo object bằng từ khóa new

III. 16 BƯỚC RUNTIME THEO JAVA VISUALIZER​

STEP 1 — JVM khởi tạo process(là một chương trình đang chạy trong hệ điều hành)

Tại sao có main:7?

  • JVM không biết “dòng 7”
  • JVM chỉ biết bytecode index
  • main:7 là do Java Visualizer map bytecode → source line

PC Register(là một vùng nhớ nhỏ dùng để lưu địa chỉ của bytecode mà thread đang thực thi) trỏ tới bytecode đầu tiên của method main. Công cụ hiển thị nó thành main:7 vì đó là dòng source tương ứng.

Hệ điều hành tạo một PROCESS mới

Process này chứa:

  • Heap(là vùng nhớ dùng để lưu object và instance của class.)
  • Method Area(là nơi lưu thông tin của class sau khi được load.)
  • Stack(là 1 thành phần của thread để lưu Local variables,Reference tới object,Operand Stack,Thông tin gọi method)
  • PC Register(à một vùng nhớ nhỏ dùng để lưu địa chỉ của bytecode mà thread đang thực thi)
  • Native Method Stack(Dùng khi Java gọi native method (viết bằng C/C++))

Đây gọi là JVM Runtime Data Areas

ClassLoader bắt đầu hoạt động

JVM không chạy ngay main.

Nó phải:

  • Load class Main
  • Load class Student

Cơ chế: Application ClassLoader sẽ:

  • Đọc file Main.class
  • Đưa bytecode vào Method Area

STEP 2 — Tạo Main Thread

JVM tạo:

  • Main Thread(là thread đầu tiên khi chương trình java bắt đầu chạy )
  • Stack (Mỗi thread có một Stack riêng, và JVM tạo một Stack Frame)
  • Frame main(là Stack Frame được tạo ra khi method main() được gọi.)

Khi Main Thread được tạo, JVM cấp cho thread này một Stack riêng, và push một stack frame cho method main() vào Stack; frame này chứa một local variable array rỗng và một operand stack rỗng và PC Register được đặt vào đầu bytecode của main (trong Visualizer công cụ hiển thị nó như dòng số tương ứng với source, nhưng thực tế JVM chỉ biết chỉ số bytecode).

operand stack là một vùng nhớ nằm bên trong mỗi Stack Frame để Lưu trữ toán hạng (operands) và kết quả trung gian khi JVM thực thi bytecode.

STEP 3 — new Student()

JVM gặp new Student().

  • JVM cấp phát một object trong Heap
  • Field age được gán mặc định = 0

Stack lúc này:

  • Vẫn chỉ có frame main().

<init> là tên đặc biệt trong bytecode dành cho constructor. Trong frame <init>, local variable đầu tiên luôn là:this this là:Reference tới object đang được khởi tạo.

Khi thực thi lệnh Student s1 = new Student();, JVM nhìn thấy bytecode tạo object mới — nó cấp phát một vùng nhớ trong Heap cho một Student với field age mặc định là 0, push reference tới object này lên operand stack của frame main().

STEP 4 — Gọi constructor

jvm gọi constructor <init> bằng cách tạo một stack frame mới cho <init> và push vào Stack. Frame <init> chứa một biến local đầu tiên là this this là reference trỏ tới object mới trong Heap, giúp constructor biết đối tượng nào đang được khởi tạo.

STEP 5 — Constructor return

Khi constructor hoàn tất, frame <init> được pop khỏi Stack trở lại frame main.

STEP 6 — Gán cho s1

trong frame main(), JVM lấy reference mà constructor trả về và lưu vào vị trí local variable của s1, vì vậy lúc này trong Stack, frame main() có entry s1 chứa một reference trỏ tới một object Student trong Heap, còn trong Heap tồn tại một object Student với age = 0

STEP 7 — s1.age = 20

JVM làm gì?

  • Tìm reference s1 trong Stack
  • Theo địa chỉ sang Heap
  • Tìm field age
  • sửa giá trị = 20

Khi JVM thấy s1.age = 20, nó lấy reference từ s1 trong Stack, theo địa chỉ đó vào Heap, tìm field age của object và sửa nó thành 20; lúc này Heap chứa object Student với age = 20.

STEP 8 — Student s2 = s1

JVM KHÔNG tạo object mới.

Nó chỉ:

  • Copy giá trị reference của s1
  • Gán cho s2

Tiếp theo Student s2 = s1 không tạo thêm object mà chỉ copy giá trị reference từ s1 sang s2 trong frame main(), vì vậy cả s1 và s2 trong Stack đều trỏ tới cùng một object trong Heap.

=> s1 và s2 trỏ cùng 1 object.

STEP 9 — s2.age = 25

JVM:

  • Lấy reference từ s2
  • Trỏ tới object trong Heap
  • Đổi age = 25

Khi chạy s2.age = 25, JVM lại truy cập object trong Heap thông qua reference của s2 và cập nhật field age trong Heap thành 25; vì cả hai reference trỏ cùng một object, nên s1.age và s2.age đều bằng giá trị 25 này

STEP 10 - int x = 10

khi gặp int x = 10, JVM lưu giá trị nguyên 10 trực tiếp vào một ô trong local variable array của frame main()

Heap không thay đổi

STEP 11 — int y = x

int y = x là bản sao giá trị 10 từ x sang y, nên trong Stack giờ đây x và y là hai biến nguyên với giá trị 10 riêng biệt, hoàn toàn không liên quan tới Heap.

Không có reference ở đây

STEP 12 — Chuẩn bị println đầu tiên

JVM làm:

-Lấy dữ liệu từ Stack hoặc Heap

  • Đẩy vào operand stack
  • Gọi phương thức println()

Khi đến các lệnh System.out.println, JVM lấy lần lượt các giá trị cần thiết từ Stack hoặc truy cập field từ Heap qua reference, push chúng lên operand stack và gọi các method println()

STEP 13 — Gọi println()

Tương tự bước 12

STEP 14 — println x

Tương tự bước 12

STEP 15 — println y

Tương tự bước 12

STEP 16 — main() kết thúc

Stack lúc gọi println: Frame println() Frame main()

Khi in xong:

  • Frame println() bị pop.

JVM tạo thêm các stack frame tạm thời cho mỗi call và pop chúng sau khi in xong.

Stack rỗng.

Object trong Heap không còn reference.

  • Garbage Collector sẽ dọn sau.

Cuối cùng khi main() kết thúc, JVM pop frame main() khỏi Stack, khiến Stack trống, còn object Student trong Heap lúc này không còn reference nào trỏ tới nên eligible for garbage collection; Heap vẫn chứa object đó cho đến khi GC chạy thu gom.

IV. TỔNG KẾT BỘ NHỚ​

Thành phầnLưu gì
Method AreaMetadata, bytecode, constant pool
HeapObject
StackPrimitive + Reference
PC RegisterVị trí bytecode hiện tại

V. Kết luận​

Tham khảo slide chi tiết tại đây :

  • 🔗 https://www.canva.com/design/DAHBYC9gqew/Qj0cc0miT3og0gFKV8UZJw/edit

Cốt lõi cần nắm :

  • Object luôn nằm trong Heap
  • Reference nằm trong Stack
  • Primitive nằm trong Stack
  • Method call → tạo Stack Frame
  • Constant Pool lưu symbolic reference
  • Execution Engine đọc bytecode
  • GC dọn object khi không còn reference

Qua ví dụ đơn giản này, ta thấy:

JVM không chỉ “chạy code”, mà:

  • Load class
  • Xác minh bytecode
  • Quản lý bộ nhớ
  • Thực thi theo kiến trúc stack
  • Gọi native code
  • Thu gom rác tự động
